# What's New in v5.3.0

## New

- **Your history no longer lives next to the program.** Up to now RADCounter kept your settings, your database and your logs in whatever folder you unzipped it into. That tied years of work to a *folder* — and folders move. Extract a newer download somewhere else and RADCounter opened blank while your history sat two folders away. From this version they live in one fixed place per person: `%LOCALAPPDATA%\RADCounter`. The program itself can be anywhere, be replaced, or be re-downloaded, and your history does not care. The move happens once, on the first start of this version, and it is a **copy** — nothing in your old folder is changed or deleted, and a note is left there saying where things went. Every file is checked by size afterwards, and if anything goes wrong at all the session simply carries on reading and writing where it always did and tries again next time.

- **It takes the copy with the most studies, wherever that copy is.** RADCounter now looks across your whole user folder, not just beside the program you started, because several copies is the normal case rather than the odd one — "RVUCounter (7)" is a real folder name from a real reader, and the one you happen to double-click is not necessarily the one holding your work. The database with the most studies is carried across, together with the settings file that belongs to *that* folder. Databases are never merged: the privacy key that hashes your accession numbers is generated per installation, so the same study in two folders carries two different hashes, and merging would silently count it twice.

- **The leftover copies are cleared away.** Once your history is safely in the new place, the other extracted copies of RADCounter go to the **Recycle Bin** — not deleted, recycled, so you can put any of them straight back yourself with no help from anyone. This is not about tidiness. An abandoned folder still holds a working RVUCounter.exe, so the old icon you have always clicked still starts an old build on an old database, and that is the actual problem. It is deliberately cautious: it refuses to remove anything holding *more* studies than was kept, it only touches a folder that genuinely contains RVUCounter.exe or a RADCounter database, and it refuses your profile, Desktop, Documents, OneDrive root and any drive root outright.

- **One Desktop shortcut, pointing at the copy that actually runs.** A shortcut you made yourself is re-pointed rather than duplicated, and nothing on your Desktop is deleted.

- **Run it from inside the zip and it now unpacks itself properly.** v5.2.7 began refusing to run from inside the downloaded zip, which was right but left you to work out what to do next. It now finds the zip it was started from — proving the match by file size and checksum, not by name — extracts the whole thing into a proper folder, and starts from there. If it cannot find the zip it still refuses, and walks you through right-click, Extract All.

- **Starting with nothing brings your history back.** On a new PC, or any time RADCounter starts with no studies at all, it offers your most recent OneDrive backup, showing the date and the number of studies before it touches anything. It only ever offers this when there is nothing to lose, and a half-synced backup is skipped in favour of the one before it. A backup holds the database and not your privacy key, so a payroll reconcile over a restored period still needs the settings folder from the old PC — the prompt says so on screen.

- **OneDrive backup is on unless you turn it off.** It used to be off, which meant anyone who never opened the Backup tab had no backup at all — and that was most people. It is a file copy into a folder you already sync, so it costs you nothing, while losing a year of pay data to a dead laptop costs rather more. Existing settings are switched on once, and after that it is yours to control.

- **Windows' download block is cleared automatically.** Windows marks every file that comes out of a browser-downloaded zip and then refuses to run a marked program. RADCounter now clears that mark from its own folder on startup, so the copy you just extracted starts instead of being silently blocked.

## Fixes

- **"Backup Now" on a box you have just ticked.** Tick "Enable OneDrive backup", press "Backup Now" straight away, and you got an **empty** warning dialog — no message on screen and not one line in the log to work from. Two separate faults, both fixed. The button now saves what is on screen before it runs, so it acts on the box you can see rather than on the old saved value. And when a backup does not run, the dialog prints the reason instead of printing nothing. Every skipped backup now also writes a line to the log, so the next one of these is diagnosable from the log alone.

- **"run me first.bat" no longer dead-ends.** Run it while RADCounter is open and it used to print "close it first" and exit — no install, no Desktop shortcut, no offer to start anything. Someone who double-clicked the program before running the batch file was left with an app running out of Downloads and no icon anywhere, which reads exactly like "I installed it and now I cannot launch it". It now offers to close RADCounter, waits for it to go, forces it if it will not, confirms it is gone, and carries on. Only a process that genuinely will not close stops it now, and it points you at Task Manager when that happens.
